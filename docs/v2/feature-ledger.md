# Kontainer v2 feature traceability ledger

Status: planning baseline; no implementation is claimed

Audit date: 2026-08-19

This ledger closes the mechanical mapping gap identified by the completeness review. It contains exactly one planning row for each of the 411 stable V1 IDs in v1-parity.md and a separate table for all 12 V1-Q archaeology questions. Approved ADRs take precedence, followed by the consolidated decision register, then the named normative owner report. A decision-blocked row is intentionally not a guessed product decision.

The status column is workflow state, not a claim that open work is implemented. Open is the default. Decision-blocked means the acceptance contract cannot close until every named open decision—or the explicitly requested new ADR candidate—is resolved. No row currently uses not-applicable; evidence-only and archive rows still require auditable evidence.

## Machine-check contract

- Stable row selector: table lines matching ^\| V1-(?!Q-)[A-Z]+-[0-9]{3} \| in this file.
- Question row selector: table lines matching ^\| V1-Q-[0-9]{3} \|.
- Stable source selector: the same stable-row expression against v1-parity.md.
- Required stable count: 411; required unique count: 411; required question count: 12.
- Stable IDs in this ledger must equal the source set exactly: set subtraction in either direction must be empty.
- Every stable row has exactly ten cells in this order: V1 ID; concise behavior; v1 classification; v2 disposition; target gate/profile; normative owner report/section; replacement feature or contract ID; acceptance evidence/scenario; blocking ADR-CAND IDs; status.
- Allowed dispositions: migrate visible capability; repair; fold into another contract; evidence-only; migrate data; archive; defer; reject; remove.
- Replacement IDs match V2-FEAT-[0-9]{3} or V2-EVID-[0-9]{3}; statuses are open, decision-blocked, or not-applicable followed by a rationale.

Read-only verification method: extract both ID columns with a line regex, sort them, assert uniqueness with uniq -d, and compare with comm in both directions. A parser must additionally split unescaped Markdown pipes, assert ten stable cells, validate enums/ID formats, and recompute the summaries below. The generation audit performed those checks before this file was written.
